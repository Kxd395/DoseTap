# Excel row contrast after sorting

Date: September 22, 2026
Plane: DOSETAP-13, In Progress
App: 0.4.19 (64)
Baseline: GitHub main `b75a5bc`, build 63
Scope: Workbook styles; exported records, calculations and schema are unchanged.

## Reproduction and repair

Native Mac Excel review of the owner's build-63 export found dark, low-contrast
rows after sorting and reopening. The original file was preserved. The writer
used an unfilled default format for plain body cells, paired with dark text.

The repair gives every emitted cell an explicit nonzero format and opaque
background. Body text, notes, links and blank placeholders use pale blue-gray
or pale aqua. The custom table style defines its base and both row bands.
The implicit Normal format remains unfilled and distinct from all body formats.

Native testing was necessary: making the default format and body format both
white or both tinted passed XML contrast checks but still produced black rows
after sorting. Adding the first row band alone also did not fix that candidate.
Excel's saved XML coalesced the identical plain body format into default style
zero, while the aqua rows retained an explicit style. Keeping Normal distinct
resolved the observed failure in the same native workflow. No black fill was
persisted in the failing saved XML; a particular appearance setting or internal
Excel rendering cause has not been established.

Direct row colors can move with sorted records, so adjacent rows can share a
color after sorting. This delivery repairs readability; it does not promise
automatic alternating bands after arbitrary sorts. Numeric formats, links,
chart definitions, table names/ranges and all 15 worksheets retain their prior
behavior. Missing values remain blank, and Overview remains a fixed snapshot.

## Validation

The final candidate was generated by the production Swift writer from a
previously supplied finalized Studio archive, kept outside Git and Plane. It
contains that archive's older records and metadata; it is not a newly exported
build-64 phone archive.

- Native Mac Excel opened the candidate without a repair prompt. Treatment-date
  ascending sort retained readable text on both backgrounds.
- Filtering Nights to included summaries displayed 201 of 208 records. The
  filter and readable rows survived save, close and reopen.
- After clearing the filter, Apple Health sleep duration sorted numerically
  descending. Saving, closing and reopening again retained the order and both
  readable row backgrounds.
- Independent ZIP readback found only `xl/styles.xml` changed from the prior
  writer for the same input. Native Excel save/readback preserved all 15 sheets,
  table names/ranges/columns and 208 Nights identities. Text and types matched
  exactly across 1,882,665 compared cells; numeric serialization differences were
  within floating-point precision. The final table had no hidden rows or active
  filter, and missing durations remained blank.
- Core build and 748 XCTest plus 43 Swift Testing cases passed. The two new
  tests resolve emitted cell formats, fonts and fills, require explicit nonzero
  formats, check opaque colors and at least 4.5:1 declared contrast, and cover
  table bands, notes, dates, numbers, links and genuinely blank placeholders.
  Their initial missing-fill regressions failed before the repair. These XML
  tests do not replace native rendering evidence.
- Six iOS integration cases passed: ExcelExportTests and
  ExportSourceSnapshotTests, on the existing iOS 26.5 export simulator.
- The native repeated-export UI journey passed after a test-only reveal fix.
  The first attempt failed before export when XCTest queried the button at the
  list's lower edge. The test now scrolls it fully into view before querying
  hittability, then retains the real button tap and both completed share-sheet
  assertions. This does not change the production Settings workflow.
- Unsigned simulator and signed device builds passed. App metadata is 0.4.19
  (64), and strict code-signature verification passed. USB installation succeeded
  without uninstall/reset; independent device app metadata confirmed 0.4.19 (64).
- All four app/staging version configurations, Plane workflow (15 tests,
  80 assertions), SSOT, documentation, architecture and whitespace checks passed.
  All 13 protected baseline file hashes and the supplied original workbook were
  unchanged. Independent source and native-artifact reviews found no blockers.

PR checks and final integration are recorded in the same Plane workpad when
verified. Personal workbooks, screenshots and source records remain outside the
repository and tracker.
