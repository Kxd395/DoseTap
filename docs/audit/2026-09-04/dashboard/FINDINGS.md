## Actual data flow and competing sources of truth

- **Local doses/events:** EventStorage SQLite → SessionRepository identity resolution → DashboardDerivedDoseMetrics → night aggregate → range-filtered metrics → cards/charts. Retrospective dose timestamps come from recorded events; current-session cache is not a second dashboard authority. Shared MedicationTiming owns in-window classification (150 minutes inclusive to 240 exclusive).
- **Surveys:** Stored morning/pre-sleep records → existing repository accessors → saved answers and per-field observed cohorts. Completion status and missingness are separate from answer values. Surveys describe saved responses, including retained/default answers; they do not establish clinical prevalence.
- **Sleep:** Apple Health and WHOOP remain separate observations. The selected provider owns comparison sleep values; recent-night rows show both when available. No hidden fallback. Local All Time and provider retrieval scope are different: client refresh requests up to 120 Health nights and 30 WHOOP days, disclosed in Data.
- **Presentation state:** One dashboard model owns range/source/loading/error; section choice is local view state. No new persistence or cache was introduced. This avoids another source of truth. The user's nightly wake override, Typical Week, supply counts and alarm rules were not changed.
- **Remaining boundaries:** Provider mapping uses existing local night/time-zone semantics; travel parity needs real data. SessionRepository still resolves one canonical identity per date; this audit does not prove every legacy multi-session import is unambiguous. DoseCore's historical “effectiveness” API names remain for other consumers; the shipping iOS dashboard no longer presents those names as clinical judgments.

**Added now from existing data:** early/late/skipped/pending/unrecorded outcome breakdown, extra-dose count, honest bathroom count, WHOOP light/awake stages, source coverage and sample labels. These solve concrete gaps without new dependencies or data collection.

**Useful next additions, not silently shipped:** per-metric sample sizes and exportable underlying rows for every subgroup; median/range of valid intervals; optional “days since logged bottle start” and “reorder date” status using the existing supply repository; symptom-frequency drill-downs from saved flags. These need small presentation/calculation additions, not a rewrite. Bottle averages need at least two logged starts and must be labeled as incomplete when tracking is optional.

**Needs better source evidence first:** wake-time consistency versus the plan actually in force on each historical night; reliable long-range wearable comparisons beyond current fetch windows; minute-level bathroom wake duration; medication effectiveness or causal treatment recommendations. Current settings cannot be retroactively substituted for historical plans, and log counts cannot supply missing durations.
