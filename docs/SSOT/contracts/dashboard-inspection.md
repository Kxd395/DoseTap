# Shared dashboard inspection

Dashboard routes retain one canonical aggregate observation identity, reporting range, selected sleep source and applicable inspection filters. Changing a filter, refresh or route never chooses a replacement observation implicitly. Same-date sessions remain distinct. A selected observation excluded by the current view remains selected with a visible explanation.

`visibleInspectionNights` applies the published treatment-night range, dose pattern, exact reviewed work phase under the selected planned/confirmed basis, and source-specific context stratum. Missing work associations are Unknown only after a successful complete local read; an unread or failed work/context source is not an empty valid history. A requested filter whose source is not ready fails closed with `inspectionFilterIssue`. A valid filter with no matching records produces an ordinary empty result.

Work context is read once per complete refresh. Planned and confirmed classifications are cached for the same immutable document revision, canonical observation IDs and published as-of timestamp. Per-row rendering does not query storage or move the analysis clock. Refresh invalidates classifications while retaining original observations and selection; the cache is republished only with the matching complete source snapshot. There is no fallback date join.

Metric eligibility remains specific to each named outcome, source and endpoint basis. Partial values are excluded by default and may enter compatible summaries only when explicitly selected. Independent daytime observations use civil-day membership; night-level dose/work filters do not silently discard daytime observations and must be disclosed as inapplicable where no explicit association exists.

The first new, explicit complete pre-sleep save captures the currently reviewed work-plan revision in the same SQLite transaction as its questionnaire and pre-sleep record. The immutable binding is the saved pre-sleep record ID. A date placeholder is not exported as a canonical session identity; only an actual active session ID may be captured. Skipped entries, imported records, existing drafts, retries and historical edits never backfill or rewrite prospective knowledge. A capture failure rolls back the whole save and retains the user's unsaved form. No configured work context means no snapshot, not a fabricated roster.
