# Work-block context

Version 1, DOSETAP-45. Dashboard work context is independent of wake scheduling, medication, alarms and session lifecycle. No existing schedule is migrated into attendance or historical roster coverage.

- Roster revisions have explicit inclusive effective dates, timezone, weekday set, recorded time and optional planned duration. Unknown start/end times stay absent. Overlapping effective revisions resolve by recorded time for the selected analysis snapshot.
- Planned context uses roster/exception records available at the reviewed sleep association's planning timestamp; confirmed context uses explicit attendance only. Scheduled never means Worked. Corrections append revisions and preserve earlier snapshots.
- A reviewed main-sleep association explicitly supplies adjacent waking dates in one timezone. Consecutive local dates support the daytime-shift rule; ambiguous/overnight associations remain Unknown. Naps cannot classify or advance a main-sleep index.
- No/Yes is Entering; Yes/Yes is Between only in the same consecutive-date work block; Yes/No is After; No/No is Off. Unanswered work status is Unknown. Block identity includes the roster revision and first work date; unknown boundaries retain unknown block counts.
- First post-block main sleep has index 1. Later off-block index stays unknown without a reviewed uninterrupted episode sequence. No recovery, exact actual hours, causation or optimal-dose result is inferred.
- Explicit phase overrides require a reason, preserve underlying observations, and carry override provenance. Analysis exports contain basis, classification version, schedule revision, phase, missingness and metric definition.
- SQLite retains the append-only context revisions behind SessionRepository. Failed/stale writes publish no success; read failures block editing. Dashboard profile/matrix use one selected outcome, separate labels for phase, eligible/missing counts and distinct known blocks. Actual outcomes never use planned shift duration as measured sleep.
- Work-date revisions may explicitly update or clear scheduled start/end and planned break timestamps. Shared date resolution keeps their source IDs and document revision; a midpoint requires two valid scheduled endpoints and planned work. A cancellation or unknown work plan cannot become a scheduled prompt. Scheduled times never establish attendance.
- Comparison grouping is exclusive: none, work phase, or spacing reference. Work-phase mode uses one phase label/color/shape mapping; spacing-reference markers never carry dose count. CSV preserves grouping, selected phase/position and matrix encoding. Reference wording stays visible and non-prescriptive.
- Profile/scatter axes use all observations in the selected reporting window, so phase filtering cannot rescale the comparison. Matrix cells choose categorical phase fill or continuous value intensity, never both. Distinct context strata remain separate summaries; unknown strata are not pooled across observations.
- A prospective plan snapshot is captured only on an explicit successful pre-sleep save. It pins the append-only roster and occurrence prefix lengths plus the source document revision, capture time and pre-sleep record identity. Later backdated corrections cannot enter that prefix. Historical reviews never manufacture a prospective snapshot. A missing referenced snapshot stays unknown. Writing a prospective snapshot upgrades the document to schema 2, preventing a schema-1 reader from editing away unrecognized history.
- Shift events have a stable occurrence ID, immutable revision ID, explicit source/status, optional block/position/cardinality and independent scheduled/actual endpoints. Exact-instant projection uses half-open intervals and returns every candidate. Planned events never establish attendance; confirmed projection requires explicit Worked and reported-minute actual endpoints. Missing/approximate/future actual evidence cannot produce precise actual totals. No match never means Off.

- Exact-ID batch lookup indexes eligible associations once. The latest recorded timestamp wins; equal timestamps retain the first stored association, matching the existing single-record lookup. Unrequested IDs and future revisions remain excluded.
- Comparison rows retain the referenced prospective snapshot ID separately from the review association revision; exports include the inclusive built-in spacing reference bounds of 150 and 240 minutes. Capture at the history limit must fail without mutating the document or revision.
- Work context reads require an exact SQLite TEXT payload with valid UTF-8 and complete JSON; BLOB coercion, embedded-NUL truncation and incomplete statement reads are rejected. Prospective capture participates in the pre-sleep insertion transaction and never commits independently.

- Work-cycle comparisons retain canonical metric evidence (source, definition version, state, raw value, reason and interval bounds) separately from numeric contributions. Partial values require the shared explicit inclusion policy; no-Dose-2 remains Not applicable. An exact physician period requires both metric endpoints inside its start-inclusive/end-exclusive interval. Missing/outside bounds withhold contributions without deleting evidence.
- Selected-period and monthly summaries group by metric/source/definition, work phase, position and compatible regimen/content stratum. First post-block and later off-block remain separate; unknown strata are observation-specific. Denominators distinguish eligible, unavailable, partial, included partial and not-applicable observations plus distinct known blocks. Missing calendar dates do not imply missing expected work-phase observations. Repeated identical IDs count once; conflicting identities cannot contribute values.

- Shared comparison CSV omits free-text detail and override notes by default while preserving the override flag, record revisions and source provenance. A future reviewed opt-in may include notes explicitly; changing the default is not permitted.
